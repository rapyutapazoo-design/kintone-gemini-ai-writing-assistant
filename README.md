# 🏢 Kintone向け AI文章作成アシスタント（Claude／Gemini対応）プラグイン

Kintoneアプリ上で、生成AI（Claude／Gemini API）を活用して「件名」と「本文」の下書き作成・要約を行うプラグインです。もともとはマンション管理組合の「意見書アプリ」向けに開発しましたが、現在は意見書・お問い合わせだけでなく、タスク説明文・業務マニュアル・議事録・業務連絡・住民向けお知らせ・汎用ビジネス文書・メール文面など、幅広い文章作成業務に対応する用途プリセットを備えた汎用プラグインとして拡張されています。

## ✨ 主な機能

1. **文章の起案サポート（利用者向け）**
   * 簡単なメモやキーワードを入力するだけで、AIが「件名」と「本文」のドラフト（下書き）を自動生成します。
   * 文章の長さは、選択肢フィールド（ドロップダウン／ラジオボタン）と連動して指定できます。フィールドの選択肢を追加・変更すると、自動でマッピング表に反映されます。
   * 出力フォーマット（見出し＋箇条書き／箇条書きのみ／段落文／番号付き手順など）を用途に応じて設定できます。
2. **要約機能（管理者向け）**
   * 長文で複雑な文章の内容を、資料として扱いやすいようにワンクリックで要約します。
   * 要約結果は、見出しや箇条書きを用いた見やすいレイアウトで専用フィールド（通常テキスト・複数行テキスト・リッチエディターに対応）に自動保存されます。
3. **用途プリセット（9種類）**
   * 意見書・お問い合わせ・業務連絡・住民向けお知らせ・タスク説明文・業務マニュアル・議事録・汎用ビジネス文書・メール文面の9種類のプリセットから選ぶだけで、プロンプト・ボタン文言・フォーマット・要約ON/OFFをまとめて設定できます（詳細は後述）。
4. **出力先の上書き保護**
   * 件名・本文にすでに入力内容がある状態でAI生成を実行すると、上書きしてよいか確認ダイアログを表示します（設定でOFFにできます）。
5. **セキュアなアーキテクチャ**
   * Kintone標準のプロキシAPI（`kintone.plugin.app.proxy`）を利用しており、生成・要約のAPIキーはプロキシ側で付与されます。管理者の設定画面では、保存済みキーを使ってモデル情報を取得します。
6. **モデルの動的取得と実疎通確認**
   * プラグイン設定画面でAPIキーを入力すると、そのキーで利用可能なGeminiモデルの一覧をその場で取得します。
   * モデルを選択すると、モデル情報の取得でアクセス可否を確認します。文章生成は実行しないため、実際の生成成功や応答速度を保証するものではありません。
7. **フィールド・プロンプトの外部化（複数アプリ対応）**
   * 対象フィールドコード・ボタン設置スペースID・プロンプト文面・ボタン文言・文字数マッピング・フォーマットをすべて設定画面から変更できます。ソースコードを直接編集することなく、様々なアプリで同じプラグインを利用できます。
8. **プロンプトの自動退避・復元（任意機能）**
   * 「AIへの指示・メモ」を生成成功時に自動でクリアしつつ、クリア前の内容を退避先フィールドに世代管理で保存し、必要なときにボタンひとつで復元できます。詳細は後述の「プロンプトの自動退避・復元機能」を参照してください。

## 🛠️ 開発・ビルド環境のセットアップ

プラグインのコードを修正し、新しくパッケージ化する際の手順です。

### 1. 依存ライブラリのインストール
```bash
cd ai-writing-assistant-plugin
npm install
```

### 2. プラグインのビルド
```bash
npm run build
```
ビルドが成功すると、`ai-writing-assistant-plugin/dist/` ディレクトリ内に `plugin.zip` が生成されます。

> **Note**: ビルドには `private.ppk`（秘密鍵）が必要です。このファイルはセキュリティの観点からリポジトリには含まれていないため、初回開発時はKintone公式ツールを用いて新規に鍵を生成するか、管理者から安全な経路で取得して `ai-writing-assistant-plugin` ディレクトリ直下に配置してください。

## 🔢 文字数フィールドの作り方（推奨）

文章の長さを利用者に選ばせたい場合は、対象アプリに「ドロップダウン」または「ラジオボタン」フィールドを追加し、以下の選択肢を設定することを推奨します（設定画面の「4. 生成オプション」にも同じ推奨リストとコピー用ボタンがあります）。

```
指定なし
100字程度
200字程度
400字程度
600字程度
800字程度
1200字程度
```

フィールドを作成したら、プラグイン設定画面の「文字数の指定に使うフィールド」で選択すると、その場で選択肢がマッピング表に自動反映されます。表の右列に選択肢ごとの指示文を入力してください（未入力のまま保存すると、警告は出ますが保存はブロックされません）。文字数フィールドを設定しない場合や、マッピングを1件も入力しない場合は、既存の互換動作（200文字／400文字／600文字を含む選択肢を判定するハードコード動作）がそのまま使われます。

## 💾 プロンプトの自動退避・復元機能

「AIへの指示・メモ」欄をAI生成のたびに手動で消す運用や、内容を他人に見られたくない（秘匿したい）運用向けに、生成成功時に指示・メモを自動でクリアしつつ、クリア前の内容を別フィールドへ世代管理で退避し、あとから復元できる機能です。既定はOFFで、設定を変更しない限り既存アプリの動作は一切変わりません。

### 設定手順

1. 対象アプリに、退避専用の**文字列（複数行）フィールド**を1つ追加します（リッチエディター・文字列（1行）は選択できません）。
2. 復元ボタンを置くための**スペースフィールド**を1つ追加します。
3. プラグイン設定画面を開き、以下を設定します。
   * 「3. フィールド設定」の「プロンプト退避先フィールド」に手順1のフィールドを指定
   * 「3. フィールド設定」の「復元ボタン設置スペース」に手順2のスペースを指定
   * 「4. 生成オプション」の「生成後に指示・メモを自動で削除する」をONにする
   * 必要に応じて「退避の文字数上限」「復元ボタン文言」を調整する
4. **「AIへの指示・メモ」フィールドの必須設定を外してください。** 自動削除機能はクリア後に入力欄を空にするため、必須設定のままだと保存時にエラーになります（設定画面にも警告が表示されます）。
5. 設定を保存し、アプリを更新すると機能が有効になります。

### 動作の概要

* 下書き生成が成功すると、「AIへの指示・メモ」の内容を退避先フィールドの先頭に新しい世代として追記し、入力欄を自動でクリアします（退避への追記と入力欄のクリアは同一の保存処理で行われるため、途中状態が発生することはありません）。
* 退避先フィールドが未設定の場合は、復元不可の単純クリアとして動作します。
* 復元ボタンは、退避先に内容がある場合のみ表示されます。退避が1件のときはワンクリックで即復元、2件以上のときはモーダルで世代を選んでから復元します。復元しても退避先フィールドの内容は変化しません（読み取り専用として扱われます）。
* 生成に失敗した場合・タイムアウトした場合・上書き確認をキャンセルした場合は、入力欄はクリアされません。

### 秘匿目的で使う場合の注意

「AIへの指示・メモ」の内容を他の利用者に見せたくない場合は、**入力欄フィールドと退避先フィールドの両方**にアクセス権設定（フィールドの閲覧・編集権限）を行ってください。退避先フィールドだけ制限しても、入力欄自体は生成前に他人が閲覧できてしまいます。また、退避先フィールドを「作成者のみ閲覧可」のように制限すると、他の利用者の画面では自動的に復元ボタンが非表示になります（退避先の値が読み取れない＝空とみなされるため）。

**編集画面で生成すると、kintoneの標準機能である変更履歴に本文・件名・入力欄クリアの痕跡が残ります。** 作成画面（レコード新規作成時）で生成する場合は変更履歴が存在しないため、痕跡は残りません。厳密に秘匿したい場合は、作成画面でのみ生成する運用を検討してください。

### 保持上限について

退避先フィールドの文字数上限は既定100,000字（世代あたりの分量にもよりますが、目安として約280世代分）です。上限を超えると、古い世代から自動的に削除され、その旨を示す注記行が追記されます。設定画面で0を指定すると無制限になります（文字列（複数行）フィールドの技術上限は実測で約525万字です）。

## 🔁 複数アプリでの利用について

AI連携プラグインは ai-writing-assistant-plugin に一本化しています。意見書アプリ・お問い合わせアプリ以外でも、同じプラグインを追加し、設定画面の「2. 用途プリセット」から用途に合ったプリセットを選んで適用し、「3. フィールド設定」でフィールドコードをアプリに合わせて調整して利用してください。意見書・お問い合わせアプリについては「意見書・お問い合わせ向けフィールド構造の初期値を入れる」ボタンでフィールド構成の初期値を入れられます。

## 🚀 Kintone環境への導入手順

1. **プラグインのインストール**
   * Kintoneの「kintoneシステム管理 > プラグイン」画面を開きます。
   * 「読み込む」ボタンから、ビルド済みの `dist/plugin.zip` をアップロードします。
2. **アプリへの適用**
   * 対象アプリの設定画面を開き、「プラグイン」メニューから「AI文章作成アシスタント」プラグインを追加します。
3. **設定画面での設定**
   * 追加したプラグインの「歯車アイコン（設定）」をクリックします。設定画面は6つのセクション（1. AI接続設定／2. 用途プリセット／3. フィールド設定／4. 生成オプション／5. 要約設定／6. ボタン文言・プロンプト）に分かれており、それぞれ折りたたんで表示できます。
   * 以下の流れで設定します。
     1. Google AI Studioで取得した **Gemini APIキー** を入力する
     2. 利用可能なモデル一覧が自動取得される
     3. モデルを選択するとモデル情報の取得による確認が行われる（生成は行わない）
     4. 「用途プリセット」からアプリの用途に近いものを選び、「この文面を適用」を押す
     5. 「フィールド設定」「生成オプション」「要約設定」で、対象アプリのフィールドコードに合わせて調整する
     6. 内容を確認して保存する
   * アプリの設定を更新（本番反映）すると、プラグインが稼働を開始します。

> **Note**: 更新後は設定画面のAPIキーの保存状態とモデル情報の確認結果を確認してください。キーが未設定と表示される場合は再入力して保存してください。既存アプリの更新には、同じ署名鍵で作成したZIPを使ってください。

## ⬆️ 既存アプリからのアップデート手順

既に稼働中の意見書アプリ・お問い合わせアプリがある場合、プラグインを最新版に更新しても、**使用順を設定し直さなければ、引き続きGeminiのみで生成します。ただし、バージョン11では既存アプリにも個人情報の伏せ字が既定ONで適用され、成功通知・注意表示が追加されます**。文字数マッピング・フォーマット設定・上書き保護などの新機能は、保存済みの設定値が存在しない間は自動的に既存のハードコード動作と完全に同じ結果になるよう作られています。同様に、追加された用途プリセットやフォーマットも、既に設定を保存済みのアプリには自動反映されません。利用するには設定画面を開き、「2. 用途プリセット」で新しいプリセットを選び直して「この文面を適用」を押し、保存してください。

新機能を使いたい場合のみ、設定画面を開いて「4. 生成オプション」等を調整し、保存してください。


## 🤖 AIプロバイダの設定（バージョン11）

設定画面の「AI接続設定」でClaude（Anthropic）とGeminiのキー・モデル・思考設定を指定します。Claudeのキーは[Anthropic Console](https://console.anthropic.com/)で取得します。モデルはそのキーで取得した一覧から選択してください。一覧を取得できない場合は、利用可能なモデルIDを確認したうえで手入力できます。特定のHaikuモデルが全アカウントで利用できるとは限りません。

使用する順番は次の4通りです。選択した順番に含まれるAIには、それぞれキーとモデルの設定が必要です。

- Claude優先・失敗時Gemini
- Geminiのみ
- Claudeのみ
- Gemini優先・失敗時Claude

新規設定の初期選択はClaude優先、使用順の設定がない既存アプリはGeminiのみです。保存済みのボタン文言は維持し、新規の既定文言とプリセットは「AIで…」と表示します。Claudeのみの場合も、既存アプリとの互換性のため内部設定の`gemini_model`は保持します。

生成・要約はkintoneのプラグインプロキシ経由で呼び出します。APIキーはプロキシ設定に保存し、通常のプラグイン設定値には保存しません。設定画面では管理者が入力したキーまたは保存済みキーで直接モデル情報を取得します。この確認では文章生成を行わず、実際の生成権限・品質・速度はレコード画面で別途確認します。

先のAIがタイムアウト、混雑、認証エラー、空の応答、出力途切れなどで失敗した場合は、設定した次のAIへ切り替えます。切り替え先にも同じ送信用テキストを送ります。両サービスへの送信を許容する運用でのみ併用してください。Gemini内の既存の軽量モデルへの切り替えも維持します。

Claudeの1回の待機上限は30秒、Geminiは40秒、再試行を含む全体の待機予算は90秒です。単純なタイムアウト後の切り替えは約70秒ですが、再試行がある場合はそれより長くなります。ブラウザ側で待機を打ち切っても、外部サービスでの処理をキャンセルできるとは限らず、遅れて完了した処理にも料金が発生する場合があります。

成功時にはAI名、モデル、所要時間、切り替え理由、伏せ字件数を通知します。処理記録にはプロバイダ・モデル・時間・結果区分・件数を使い、入力本文やキーは記録しません。

## 🛡️ 個人情報の自動伏せ字

既定ONです。**設定し直していない既存アプリにも適用されます。** 設定画面でOFFにした場合、入力内容は伏せ字にせず送信します。

| 対象例 | 置換後 |
|---|---|
| 電話番号（国内番号、+81形式、全角数字など） | ［電話番号］ |
| メールアドレス | ［メールアドレス］ |
| 郵便番号（123-4567、〒1234567など） | ［郵便番号］ |
| 部屋番号（101号室、三〇二号室など） | ○○号室 |

氏名・住所・生年月日は対象外です。形式による検出のため、品番などの誤検知や、省略された電話番号・「101室」などの見逃しがあります。個人情報を完全に除去する機能ではありません。

伏せ字は、下書きの入力メモ（`{{input}}`）と要約対象本文（`{{body}}`）の送信用コピーだけに適用します。管理者が設定するプロンプトの固定文には適用しません。入力欄・退避データには元の内容を残すため、それらの閲覧権限は別途管理してください。AIの出力を元の個人情報へ自動復元する処理はありません。必要な箇所は送信後に利用者が補ってください。

## 運用前の実機確認

ローカルの検証・ビルドだけでは確認できないため、本番適用前にテスト用アプリで次を確認してください。

- 各AIのキー保存、モデル一覧、下書きと要約、失敗時の切り替え。
- 選択したモデルの日本語品質、文字数指示、件名・本文のJSON出力の安定性。
- 実際の応答時間、kintoneプロキシの制限、モバイルの表示と通信。
- 伏せ字の誤検知・見逃し、元の入力と退避・復元への影響。
- 利用するAPI契約の最新料金、データ保持期間、学習利用の扱い。旧計画書の料金や将来APIバージョンの記載は確定情報として扱わないでください。

問題が発生した場合は、まず使用順を「Geminiのみ」に戻して確認します。プラグイン自体を戻す必要がある場合は、保全済みソースを同じ署名鍵でパッケージ化し、kintone側の更新条件に従って復旧してください。設定変更も戻せるよう更新前の設定を控えてください。
